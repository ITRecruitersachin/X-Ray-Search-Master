## 🎯 What Is X-Ray Search Master?

**X-Ray Search Master** is an open-source sourcing handbook designed for recruiters, talent sourcers, recruitment researchers, and talent acquisition professionals who want to become more effective at internet-based candidate discovery.

The project focuses on practical sourcing rather than theory.

It brings together:

* Boolean Search
* Google X-Ray Search

# 🚀 Quick Start

If you are new to X-Ray Search, start here:

### Step 1 — Understand the requirement

Break the job description into:

```text
Role
Title
Core Skills
Secondary Skills
Technology
Domain
Industry
Location
Company
Education
Certification
Experience
Exclusions
```

### Step 2 — Build the title cluster

Example:

```text
("Java Developer"
OR "Java Engineer"
OR "Java Software Engineer"
OR "Backend Engineer"
OR "Backend Developer")
```

### Step 3 — Build the technology cluster

Example:

```text
(Java
AND "Spring Boot"
AND Microservices
AND AWS)
```

### Step 4 — Add geography

Example:

```text
("Detroit" OR "Detroit, MI" OR Michigan)
```

### Step 5 — Combine the components

Conceptually:

```text
TITLE
+
CORE TECHNOLOGY
+
SECONDARY TECHNOLOGY
+
LOCATION
+
OPTIONAL DOMAIN
```

### Step 6 — Search multiple sources

Do not depend on a single source.

Use combinations of:

```text
Google
LinkedIn
GitHub
Resume databases
Public portfolios
Technical communities
Job boards
Company websites
Conference pages
Professional websites
```

### Step 7 — Validate

A search result is a **discovery signal**, not automatically proof of:

* Current employment
* Current location
* Current seniority
* Current technology usage
* Availability
* Employment authorization
* Visa status
* Compensation
* Interest in a new opportunity

Always validate information through appropriate recruiting processes.

# 🧩 Boolean Search

Boolean Search is the foundation of structured candidate discovery.

Core concepts include:

```text
AND
OR
NOT
-
"Exact Phrase"
(Parentheses)
```

Example:

```text
("Java Developer" OR "Java Engineer" OR "Backend Engineer")
AND
("Spring Boot" OR "Spring")
AND
(Microservices OR "Micro Services")
AND
(AWS OR "Amazon Web Services")
```

Boolean searches should be designed according to the sourcing objective rather than made unnecessarily long.

A good search balances:

```text
Precision
+
Recall
+
Relevance
```

# 🔎 Google X-Ray Search

Google X-Ray Search uses search-engine queries to discover publicly indexed information from specific domains.

A common pattern is:

```text
site:domain.com
```

Example:

```text

```

Another example:


# 🧠 Search Engineering

Effective sourcing is iterative.

The repository treats search construction as an optimization problem:

```text
                    SEARCH
                       │
          ┌────────────┼────────────┐
          ▼            ▼            ▼
      Too Broad     Balanced     Too Narrow
          │            │            │
          ▼            ▼            ▼
       Narrow        Validate      Expand
          │            │            │
          └────────────┼────────────┘
                       ▼
                 RE-RUN SEARCH
```

### If results are too broad

Consider:

* Adding a core technology
* Adding a specific title
* Adding a location
* Adding a domain
* Adding an exclusion
* Removing ambiguous terms

### If results are too narrow

Consider:

* Expanding title synonyms
* Expanding technology synonyms
* Expanding locations
* Removing non-essential requirements
* Searching another source
* Splitting one complex search into several searches

➡️ Advanced search engineering will live in:

`17-Advanced-Search/`

# ⚠️ Search Accuracy Principles

This repository follows several important rules.

### 1. Do not invent search operators

Search-engine functionality changes over time.

### 2. Do not assume platform functionality

Platform-specific behavior should be verified.

### 3. Do not assume public information is current

A public profile or resume can be outdated.

### 4. Do not assume GitHub activity equals employment

Technical contributions are signals, not proof of employment or seniority.

### 5. Do not assume title equivalence

Similar titles can represent substantially different responsibilities.

### 6. Do not assume technology equivalence

Related technologies are not necessarily interchangeable.

### 7. Do not over-constrain searches

A huge Boolean query can eliminate relevant candidates.

### 8. Do not under-constrain searches

A broad query can create excessive noise.
